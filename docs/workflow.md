\# Git Workflow Documentation



\## Objective

Demonstrate Git version control best practices using GitHub.



\## Branching Strategy

\- `main`: Stable project version.

\- `dev`: Integration branch.

\- `feature/add-documentation`: Feature development branch.



\## Workflow Steps

1\. Initialize the local Git repository.

2\. Create README.md and .gitignore.

3\. Commit the initial files on main.

4\. Push main and dev to GitHub.

5\. Create a feature branch from dev.

6\. Add workflow and interview documentation.

7\. Commit and push feature changes.

8\. Create a pull request from the feature branch to dev.

9\. Create a pull request from dev to main.

10\. Tag the completed version as v1.0.0.



\## Useful Git Commands

\- `git status`: Check working-tree status.

\- `git branch`: List local branches.

\- `git switch`: Switch branches.

\- `git add`: Stage changes.

\- `git commit`: Save a snapshot.

\- `git push`: Upload commits.

\- `git log --oneline`: View commit history.

\- `git tag`: List tags.



\## Pull Request Process

Changes are proposed and reviewed through GitHub pull requests before being merged into the target branch.



\## Release

The `v1.0.0` tag identifies the first completed version of the project.
